Preparar o computador

Começar em uma pasta vazia, sem depender de Git.

Entender os conceitos · Ferramentas e pasta de trabalhoclique para expandir

Node executa JavaScript fora do navegador; npm gerencia pacotes. VS Code é o editor. Git e conta GitHub não são necessários para a prática.

Quem faz o quê?

O VS Code edita arquivos. O Node.js executa o JavaScript necessário às ferramentas e ao servidor do Next.js. O npm instala os pacotes que o projeto utiliza. O navegador mostra a aplicação e executa sua parte interativa.

Em qual pasta estou?

O terminal trabalha na pasta indicada antes do cursor. Na etapa 1, o gerador criará uma nova pasta chamada checkpoint. Depois entraremos nela para executar os comandos da aplicação. O arquivo package.json ajuda a reconhecer essa raiz.

Os recursos extraídos são materiais para copiar, não uma aplicação pronta. A internet é necessária para baixar os pacotes; a página local será servida pelo próprio computador. Por isso, instalar antes em casa não substitui conferir o ambiente do laboratório.

Criar e iniciar o Next.js

Instalar pelo gerador oficial e abrir a página inicial.

Entender os conceitos · Gerador, dependências e servidor localclique para expandir

npx executa create-next-app; @16.4.4 fixa o gerador. checkpoint é a nova pasta. --use-npm escolhe npm, --disable-git dispensa Git e --no-cache-components desativa Cache Components para este roteiro. localhost aponta para este computador.

O que o gerador prepara?

create-next-app cria a estrutura inicial, os arquivos de configuração e os exemplos. Depois instala os pacotes necessários. Esse conjunto inicial é chamado de boilerplate: vamos aproveitar sua estrutura e alterar o conteúdo aos poucos.

package.json descreve o projeto, suas dependências e comandos. package-lock.json registra as versões resolvidas na instalação. node_modules guarda os pacotes baixados; não é a pasta em que escreveremos o site.

Por que npm run dev?

Esse comando executa o script dev do projeto e mantém um servidor local ligado. Ao salvar um arquivo, o ambiente de desenvolvimento costuma atualizar a página automaticamente. Fechar esse processo encerra o servidor; para retomar, basta executá-lo novamente na mesma aplicação.

localhost e 127.0.0.1 apontam para o próprio computador. A porta diferencia os servidores: dois projetos abertos podem estar em 3000 e 3002. Sempre confira o endereço no terminal da aplicação que você está editando.

  4. Em outro terminal, confira as versões com npm ls. Preserve package-lock.json. Ao retomar, não execute o gerador novamente.

Editar a primeira página

Entender arquivo → componente → tela.

Entender os conceitos · app, page.tsx, JSX e layoutclique para expandir

Um componente React pode ser uma função que retorna JSX. page.tsx expõe /. export default disponibiliza o componente. O layout envolve as páginas e recebe seu conteúdo em children. .tsx combina TypeScript e JSX.

Como a página chega ao navegador

app é a pasta em que o App Router organiza as páginas e os layouts. O Next.js reconhece nomes especiais de arquivos para montar a navegação.

ArquivoPapel
app/page.tsxDefine a página inicial, no endereço /.
app/layout.tsxEnvolve as páginas com uma estrutura compartilhada. Neste primeiro layout, mantém html e body.

Ao abrir http://localhost:3000/, o Next.js usa a página exportada por app/page.tsx e a apresenta dentro do layout. Use a porta que seu terminal indicar.

Lendo a função Home

function Home() declara um componente React: uma função que descreve um pedaço da interface. export default torna esse componente a exportação principal do arquivo, que o Next.js utiliza como página.

Home é um nome escolhido por nós e começa com letra maiúscula. Poderia se chamar Inicio: o endereço continuaria /, pois quem define a rota é a posição do arquivo page.tsx.

return (...) devolve a descrição da interface. O trecho com tags se chama JSX: uma sintaxe usada pelo React, parecida com HTML, escrita junto ao JavaScript. A extensão .tsx permite usar TypeScript e JSX no mesmo arquivo.

<main> identifica o conteúdo principal da página; <h1> é o título e <p> é um parágrafo. Essa tag main não é uma função de entrada do programa. Aqui ela também agrupa os elementos devolvidos pelo componente.

Em JSX, usamos className para associar classes CSS. As chaves inserem expressões JavaScript: se const titulo = "Checkpoint";, escrever <h1>{titulo}</h1> mostra o valor Checkpoint na tela.

Onde entra children?

O layout recebe o conteúdo da página em children e escolhe onde exibi-lo. No nosso layout mínimo, <body>{children}</body> coloca a página dentro do body. Mais adiante, o cabeçalho ficará no layout para aparecer em várias páginas.

Como explicar em uma frase: “O arquivo page.tsx escolhe o que aparece naquele endereço; a função Home descreve essa tela em JSX, e o layout fornece a estrutura ao redor.”

Copiar os recursos de apoio

Entender os conceitos · O que é lib e como os recursos se conectamclique para expandir

Jogo descreve um objeto; Jogo[] é uma lista. export permite importar os dados. lib é uma escolha de organização. Arquivos em public são acessados sem /public. className associa o JSX ao CSS.

lib é uma pasta especial do Next.js?

Não. O nome vem de library (biblioteca) e é uma convenção para organizar código reutilizável, funções auxiliares e dados. Neste projeto, nós mesmos criamos lib na raiz e guardamos nela a lista de jogos. Ela poderia ter outro nome; manter lib faz os caminhos coincidirem com este guia.

O caminho final checkpoint/lib/jogos.ts significa: entre na pasta da aplicação, depois em lib, e encontre o arquivo jogos.ts. Não crie essa pasta dentro de app. Criar lib não cria uma página nem um endereço no navegador.

O que há dentro de jogos.ts?

type Jogo descreve o formato esperado de um jogo: número em id, texto em titulo e assim por diante. Jogo[] significa uma lista desses objetos. O tipo ajuda o editor a apontar inconsistências; ele não é um banco de dados.

export const jogos permite que outros arquivos utilizem essa mesma lista. Na etapa 5 escreveremos import { jogos } from "@/lib/jogos";. As chaves selecionam a exportação chamada jogos; @/ representa a raiz configurada do projeto. No import, omitimos a extensão .ts. Por enquanto, basta copiar o arquivo.

Uma API substituiria lib?

Ela poderia substituir a origem dos dados, não a pasta. Hoje a lista está escrita diretamente em lib/jogos.ts. É uma lista fixa: para mudar um título ou acrescentar um jogo, editamos esse arquivo. Assim praticamos páginas e rotas sem configurar um serviço de dados.

PartePara que serve
Lista fixa em jogos.tsFornece os dados locais usados nesta aula.
APIOferece uma interface pela qual a aplicação pode solicitar dados; esses dados podem vir de um banco.
Banco de dadosArmazena e permite consultar e alterar os registros.
Pasta libOrganiza código reutilizável. Pode guardar a lista fixa ou funções que consultam uma API ou banco.

Em uma evolução do projeto, lib/jogos.ts poderia exportar uma função buscarJogos() que consulta uma API, em vez de exportar a lista pronta. As páginas passariam a chamar essa função e tratar a espera e possíveis falhas. Também é possível consultar um banco diretamente no código de servidor, sem criar uma API própria para isso.

Como explicar para a turma: “lib é uma pasta para organizar código compartilhado. Aqui ela guarda nossa lista de jogos. Em um sistema maior, os jogos poderiam vir de uma API ou banco, e lib poderia guardar o código que faz essa consulta.”

Por que separar lib e public?

lib/jogos.ts é usado pelo código através de um import. Já public/jogos/gta-6.jpg é um arquivo que o navegador pode pedir pelo endereço /jogos/gta-6.jpg. Não incluímos public na URL. O campo imagem de cada jogo aponta para uma dessas imagens.

O CSS fornece a aparência; className conecta os elementos às classes prontas. Copiar o CSS não cria os cards automaticamente: eles serão escritos na etapa 5. Agora, a mudança esperada é o estilo da página simples.

Criar Sobre e a navegação

Aprender uma segunda rota e um layout compartilhado antes da lista.

Entender os conceitos · Rotas, Link e estrutura compartilhadaclique para expandir

Uma pasta com page.tsx cria uma rota. Link permite navegação interna. O conteúdo da página muda, enquanto o layout compartilhado continua envolvendo children. CSS pronto cuida da aparência da marca e do menu.

Como aparece /sobre?

No App Router, a estrutura de pastas participa do endereço. app/page.tsx atende à raiz /. Ao criar app/sobre/page.tsx, adicionamos /sobre. Só criar a pasta sobre não cria uma página: precisamos do arquivo page.tsx e do componente exportado.

O nome da função pode ser Sobre ou outro nome de componente. Quem define essa URL é a posição do arquivo. Por isso não precisamos cadastrar a rota manualmente em uma lista separada.

Por que usar Link e layout?

Link, importado de next/link, recebe o destino em href e permite navegar entre as rotas da aplicação. Escrevemos o cabeçalho uma vez no layout: ele envolve a página que chega em children.

Ao navegar, o conteúdo central muda e a estrutura compartilhada continua disponível. Neste momento o menu tem somente Sobre e Jogos. Curtidos depende dos complementos e será acrescentado depois.

components/CurtidosProvider.tsx
"use client";

import { createContext, useContext, useState, type ReactNode } from "react";

type Contexto = {
  ids: number[];
  alternar: (id: number) => void;
  carregado: boolean;
  erro: string | null;
};
const CurtidosContext = createContext<Contexto | null>(null);

export default function CurtidosProvider({ children }: { children: ReactNode }) {
  const [ids, setIds] = useState<number[]>([]);

  function alternar(id: number) {
    setIds((atual) => atual.includes(id)
      ? atual.filter((item) => item !== id)
      : [...atual, id]);
  }

  return (
    <CurtidosContext.Provider value={{ ids, alternar, carregado: true, erro: null }}>
      {children}
    </CurtidosContext.Provider>
  );
}

export function useCurtidos() {
  const contexto = useContext(CurtidosContext);
  if (!contexto) throw new Error("useCurtidos precisa estar dentro de CurtidosProvider.");
  return contexto;
}

Salvar a seleção no navegador

Recuperar os curtidos depois de recarregar.

Entender os conceitos · Persistência, effects e hidrataçãoclique para expandir

localStorage é uma API do navegador. JSON.stringify grava texto e JSON.parse o recupera. useEffect sincroniza o componente com esse armazenamento após a hidratação. Server Components não leem localStorage. Compartilhar estado e persistir dados são problemas diferentes.

Guardar no React ou no navegador?

O estado React mantém a tela atualizada durante o uso. localStorage guarda texto no navegador entre visitas à mesma origem. JSON.stringify transforma a lista em texto; JSON.parse interpreta esse texto de volta. Isso não cria uma conta nem sincroniza outro computador.

Por que dois effects e carregado?

O primeiro useEffect lê o armazenamento após a montagem no cliente. O array vazio de dependências indica que ele não acompanha mudanças de props ou estado. A leitura descarta valores inválidos e IDs que não existem no catálogo.

O segundo useEffect acompanha o estado para gravá-lo. A verificação de carregado impede que a lista vazia inicial sobrescreva a seleção salva antes de ela ser lida. Enquanto isso, os consumidores usam carregado para mostrar a espera ou desabilitar ações.

O que é hidratação?

É a etapa em que o React conecta a lógica cliente ao HTML inicial. O servidor não tem acesso ao localStorage. Começamos com o mesmo estado inicial no servidor e no cliente; só depois lemos os dados do navegador. Isso evita que a primeira tela de cada lado seja diferente por causa do armazenamento.

O tratamento de erros mantém a seleção em memória se a gravação falhar. O endereço e a porta importam: outro navegador ou outra origem tem seu próprio armazenamento.

  2. Observe o primeiro useEffect: ele lê a chave checkpoint-curtidos-v1, interpreta o JSON, aceita somente IDs existentes e elimina duplicatas.
  3. Observe o segundo useEffect: ele só grava depois de carregado ser true. Assim, a lista vazia inicial não apaga os IDs que já estavam salvos.

components/CurtidosProvider.tsx
"use client";

import { createContext, useContext, useEffect, useState, type ReactNode } from "react";
import { jogos } from "@/lib/jogos";

const CHAVE = "checkpoint-curtidos-v1";
type Estado = { ids: number[]; carregado: boolean };
type Contexto = Estado & { alternar: (id: number) => void; erro: string | null };
const CurtidosContext = createContext<Contexto | null>(null);

export default function CurtidosProvider({ children }: { children: ReactNode }) {
  const [estado, setEstado] = useState<Estado>({ ids: [], carregado: false });
  const [erro, setErro] = useState<string | null>(null);

  useEffect(() => {
    let ids: number[] = [];
    try {
      const dados: unknown = JSON.parse(localStorage.getItem(CHAVE) ?? "[]");
      if (Array.isArray(dados)) {
        ids = [...new Set(dados.filter((id): id is number =>
          typeof id === "number" && jogos.some((jogo) => jogo.id === id)
        ))];
      }
    } catch {
      // O catálogo continua utilizável quando o navegador bloqueia o armazenamento.
    }
    // eslint-disable-next-line react-hooks/set-state-in-effect -- Lê o armazenamento externo somente após a hidratação.
    setEstado({ ids, carregado: true });
  }, []);

  useEffect(() => {
    if (!estado.carregado) return;
    try {
      localStorage.setItem(CHAVE, JSON.stringify(estado.ids));
    } catch {
      // eslint-disable-next-line react-hooks/set-state-in-effect -- Informa a falha de sincronização com o armazenamento externo.
      setErro("Não foi possível salvar neste navegador. Os curtidos ficam disponíveis nesta visita.");
    }
  }, [estado]);

  function alternar(id: number) {
    if (!estado.carregado || !jogos.some((jogo) => jogo.id === id)) return;
    setEstado((atual) => ({
      ...atual,
      ids: atual.ids.includes(id)
        ? atual.ids.filter((item) => item !== id)
        : [...atual.ids, id],
    }));
  }

  return (
    <CurtidosContext.Provider value={{ ...estado, alternar, erro }}>
      {children}
    </CurtidosContext.Provider>
  );
}

export function useCurtidos() {
  const contexto = useContext(CurtidosContext);
  if (!contexto) throw new Error("useCurtidos precisa estar dentro de CurtidosProvider.");
  return contexto;
}

Os favoritos ficam por navegador e endereço, sem sincronizar com outro computador ou conta. Se o armazenamento for bloqueado, a seleção funciona nesta visita e a página avisa que não pôde salvar.
